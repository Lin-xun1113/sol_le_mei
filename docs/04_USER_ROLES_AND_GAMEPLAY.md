# Sol了没 - 用户角色与玩法

## 角色定义

### 1. 👤 普通用户 (User)
注册并使用 Sol了没 的玩家。

**可执行操作**:
| 操作     | 指令        | 说明               |
| -------- | ----------- | ------------------ |
| 注册     | `register`  | 创建账户，选择模式 |
| 签到     | `heartbeat` | 续命，重置倒计时   |
| 存款     | `deposit`   | 向 Vault 存入 SOL  |
| 发送 RIP | `send_rip`  | 给其他用户发悼念   |

**状态变化**:
```
未注册 → 注册 → 活着 ←(签到)→ 活着
                    ↓ (超时)
                   死亡
```

---

### 2. 🦅 秃鹫 / 捡漏者 (Looter)
专门盯着快死的人，准备捡漏的玩家。

**可执行操作**:
| 操作     | 指令       | 说明                      |
| -------- | ---------- | ------------------------- |
| 宣判死亡 | `flatline` | 触发超时用户的死亡判定    |
| 捡漏     | `loot`     | 拿走 Feast 模式用户的遗产 |

**收益**:
- 成功 `loot` 可获得死者 Vault 余额的 **50%**

**策略**:
- 监控链上 UserProfile 账户
- 计算 `lastPulse + timeoutSeconds`
- 超时后第一时间调用 `flatline` → `loot`

---

### 3. 🕯️ 吊唁者 (Mourner / RIP Sender)
给其他用户发送 RIP 的社交玩家。

**可执行操作**:
| 操作     | 指令       | 说明                      |
| -------- | ---------- | ------------------------- |
| 发送 RIP | `send_rip` | 消耗 Gas 给目标用户发悼念 |

**潜在收益**:
- RIP 记录存储在链上
- 未来公共池 (reward_pool) 分配时，RIP 发送者有资格参与抽奖

**费用**:
- 仅需支付链上交易 Gas (约 0.000005 SOL)
- 首次发送需支付 RipRecord 账户租金 (约 0.00089 SOL)

---

### 4. 🏛️ 项目方 / 管理员 (Protocol Admin)
项目运营方。

**可执行操作**:
| 操作       | 指令                   | 说明                             |
| ---------- | ---------------------- | -------------------------------- |
| 初始化墓地 | `initialize_graveyard` | 一次性初始化全局账户             |
| 提取协议费 | (未实现)               | 提取 Graveyard.protocol_fees     |
| 分配奖励池 | (未实现)               | 将 reward_pool 空投给 RIP 发送者 |

**收益**:
- Graveyard 内 10% 的协议费

---

## 玩法模式

### 模式 0: 🛡️ 安全模式 (Safeguard Mode)

**目标用户**: 
- 独居人群
- 想要资产保全的用户
- 担心私钥丢失的用户

**机制**:
```
用户注册 (mode=0, 设置 beneficiary)
    ↓
定期签到续命
    ↓
超时未签到 → 死亡判定
    ↓
Vault 资金 100% 转给 beneficiary
```

**特点**:
- 无博弈元素
- 资金安全转移
- 类似传统遗嘱

---

### 模式 1: 🦅 吃席模式 (Feast Mode)

**目标用户**:
- Degen 玩家
- 喜欢博弈的用户
- Meme 爱好者

**机制**:
```
用户注册 (mode=1)
    ↓
定期签到续命
    ↓
收到其他人的 RIP
    ↓
超时未签到 → 死亡判定
    ↓
Vault 资金分配:
├── 50% → 第一个调用 loot 的人 (秃鹫)
└── 50% → Graveyard 公共池
         ├── 10% → 协议费 (项目方)
         └── 90% → 奖励池 (未来空投给 RIP 发送者)
```

**特点**:
- 高风险高回报
- PVP 竞争 (抢着 loot)
- 社交传播 (发 RIP)

---

## 典型游戏场景

### 场景 1: 正常签到
```
1. 用户 A 注册 (24小时超时, Feast模式)
2. 用户 A 每天签到
3. 永远不会死，资金安全
```

### 场景 2: 被捡漏
```
1. 用户 A 注册 + 存入 1 SOL
2. 用户 A 忘记签到超过 24 小时
3. 秃鹫 B 发现 A 超时，调用 flatline(A)
4. 秃鹫 B 调用 loot(A)
5. B 获得 0.5 SOL，Graveyard 获得 0.5 SOL
   - 0.05 SOL → 协议费
   - 0.45 SOL → 奖励池
```

### 场景 3: RIP 社交
```
1. 用户 A 发推: "我还活着 #Sol了没"
2. 用户 B、C、D 点击推文下的 [Send RIP] 按钮
3. A 的 ripCount += 3
4. 如果 A 死亡，B/C/D 有资格参与奖励池分配
```

### 场景 4: 秃鹫竞赛
```
1. 大户 A 的倒计时即将结束
2. 多个秃鹫 (B, C, D) 盯着区块时间
3. A 超时瞬间，B/C/D 同时提交 loot 交易
4. 第一个上链的人获得遗产
5. 其余人交易失败 (vault 已清空)
```

## 经济模型

```
用户死亡 (Feast Mode)
    │
    ▼
Vault 余额: 1 SOL
    │
    ├──────────────► 秃鹫: 0.5 SOL (50%)
    │
    └──────────────► Graveyard: 0.5 SOL (50%)
                          │
                          ├───► 协议费: 0.05 SOL (10%)
                          │
                          └───► 奖励池: 0.45 SOL (90%)
                                    │
                                    ▼
                              RIP 发送者们 (未来空投)
```

## 风险提示

1. **模式选择不可更改**: 注册后无法切换 Safeguard/Feast
2. **超时即死亡**: 一旦超时，无法复活
3. **Gas 竞争**: Loot 是先到先得，可能被 MEV Bot 抢先
4. **资金风险**: Feast 模式下资金可能被他人捡走
